# Безопасное обновление приложения

Цель: изменения сначала проходят проверку, и только потом попадают в `main`, откуда Render делает новый релиз.

## Как вносить изменения

1. Делать правки в отдельной ветке, не сразу в `main`.
2. Перед отправкой запускать:

```bash
npm run check
```

3. Создать Pull Request в GitHub.
4. Дождаться зеленой проверки `Release check`.
5. Только после этого вливать Pull Request в `main`.

Render должен быть подключен к ветке `main`. Тогда он деплоит только то, что уже прошло проверку.

## Что проверяется автоматически

- `server.js` синтаксически валиден.
- Основной интерфейс `index.html` не заменен короткой версией.
- На месте ключевые поля: дата, часы, минуты, паркинг, ночевка, записи, итоги, неделя и месяц.
- Google OAuth не использует хрупкое хранение `state` в памяти сервера.
- На месте серверное хранилище, аудит действий и Postgres-настройка.

## Если проверка красная

Не мержить Pull Request. Нужно открыть ошибку `Release check`, исправить указанную причину и дождаться зеленого статуса.
